# GSP532 - Build a Smart Cloud Application with Vibe Coding and MCP: Challenge Lab

This lab mixes scripted commands with two interactive pieces (Antigravity CLI and the ADK web UI) and two code files you edit (server.py via the CLI, agent.py by hand). The command blocks here auto-detect what they can; a few values come from the lab panel and are set once in Setup. Work in the Cloud Shell Editor with a terminal open, as the lab says.

## Known lab traps/bugs (read first)

1. Per-instance values. The lab writes "filled in at lab start" in many places. The real values are: your project ID (detected), project number (detected), region (detected or from the panel), the MODEL string (Task 1 .env block in the lab), the MCP server service name, and the ADK agent service name. Set the ones that are not auto-detected in Setup and every block reads them from files.
2. server.py is deliberately broken: line 11, which creates the MCP server object, is commented out (# mcp = FastMCP(...)), so every @mcp.tool() and mcp.run_async() fails with NameError: name 'mcp' is not defined. The lab tells you to fix it with Antigravity CLI (agy), but on the student account agy's model (gemini-4-carbon) is blocked by an org policy (constraints/vertexai.allowedModels), so it cannot edit the file. Fix it by hand instead (block 2a), the checker scores the working server, not how you fixed it.
4. The ID token expires. If Antigravity CLI gives an auth error in Task 3, regenerate the token and rewrite mcp_config.json (block 3a does both, just rerun it).
5. Deploys are slow: MCP server up to 10 minutes, ADK agent up to 15. On "Quota exceeded for total allowable CPU", wait a moment and rerun the same deploy.
6. In the ADK UI keep Token Streaming OFF (top right) or multi-agent tool calls stall.
7. agent.py has TODO comments you must complete in Task 4 before the local and Cloud Run deploys. Read them in the editor.
8. The checker lags. If a check fails after a step ran cleanly, wait 30-60 seconds and click again.

## Setup

Edit the 3 values that cannot be detected: the MODEL from the lab's Task 1 .env block, and the two Cloud Run service names (the lab panel / variables give them; the MCP one carries the label mcp-zoo-cloud-run-service, the ADK one cloud-zoo-run-adk-service).

```bash
echo "MODEL_FROM_LAB" > ~/model
echo "MCP_SERVICE_NAME_FROM_LAB" > ~/mcpname
echo "ADK_SERVICE_NAME_FROM_LAB" > ~/adkname
gcloud config get-value project > ~/project
gcloud projects describe `cat ~/project` --format='value(projectNumber)' > ~/projnum
gcloud compute project-info describe --format=json | grep -A1 'google-compute-default-region' | grep '"value"' | cut -d'"' -f4 > ~/region
test -s ~/region || gcloud config get-value run/region > ~/region
test -s ~/region || gcloud config get-value compute/region > ~/region
gcloud config set project `cat ~/project` --quiet
head ~/project ~/projnum ~/region ~/model ~/mcpname ~/adkname
```

You should see 6 filled values. If region is empty, set it by hand from the lab panel: `echo "us-central1" > ~/region`. The region and service names must match the lab, a wrong value deploys fine but scores 0.

## Task 1. Set up the environment and enable the APIs

### 1a. Download the code

```bash
cd ~
gcloud storage cp gs://`cat ~/project`-labconfig-bucket/labs_code.zip .
unzip -o labs_code.zip
ls ~/mcp-on-cloudrun ~/zoo_guide_agent
```

You should see server.py, local_mcp_call.py, Dockerfile in mcp-on-cloudrun, and agent.py, requirements.txt in zoo_guide_agent. If the copy fails with "bucket does not exist", the bucket name differs: find it with `gcloud storage ls | grep labconfig` and use that in the cp command.

### 1b. Write the .env file

The MCP_SERVER_URL is built from the service name, project number and region. If your project's Cloud Run URLs use a different format, block 2d corrects it with the real URL after the server is deployed.

```bash
cd ~/zoo_guide_agent
cat > .env <<EOF
MODEL="`cat ~/model`"
SERVICE_ACCOUNT="`cat ~/projnum`-compute@developer.gserviceaccount.com"
MCP_SERVER_URL="https://`cat ~/mcpname`-`cat ~/projnum`.`cat ~/region`.run.app/mcp/"
GOOGLE_GENAI_USE_ENTERPRISE=1
GOOGLE_CLOUD_PROJECT=`cat ~/project`
PROJECT_NUMBER=`cat ~/projnum`
GOOGLE_CLOUD_LOCATION=global
EOF
cat .env
```

You should see the .env with your real values filled in, no "filled in at lab start" left.

### 1c. Enable the APIs

```bash
gcloud services enable aiplatform.googleapis.com artifactregistry.googleapis.com \
  compute.googleapis.com cloudbuild.googleapis.com run.googleapis.com --quiet
gcloud services list --enabled --format='value(config.name)' | grep -E 'aiplatform|artifactregistry|compute|cloudbuild|run'
```

You should see all five APIs listed.

## Task 2. Fix and deploy the MCP server

### 2a. See the error, then fix server.py by hand

```bash
cd ~/mcp-on-cloudrun
uv run --python 3.13 server.py
```

You should see NameError: name 'mcp' is not defined at @mcp.tool(). The cause is line 11 being commented out. Uncomment it:

```bash
sed -i '11s/^# *//' ~/mcp-on-cloudrun/server.py
sed -n '11p' ~/mcp-on-cloudrun/server.py
```

The second line should print: mcp = FastMCP("Zoo Animal Data MCP Server ...") with no leading #. If line 11 is not the commented FastMCP line in your instance, find it with `grep -n 'FastMCP' ~/mcp-on-cloudrun/server.py` and uncomment that line number instead.

(The lab wants this done with Antigravity CLI, but agy is blocked by org policy on the student account, see trap 2. The hand-fix above is equivalent for scoring.)

### 2b. Run the server locally

```bash
cd ~/mcp-on-cloudrun
uv run --python 3.13 server.py
```

You should see the MCP server start with no NameError. Leave it running and open a SECOND terminal for the next block.

### 2c. Test from a second terminal

```bash
gcloud config set project `cat ~/project` --quiet
cd ~/mcp-on-cloudrun
uv run --python 3.13 local_mcp_call.py
```

You should see a CallToolResult with structured data about the walrus species. Then stop the server in the first terminal with Ctrl+C.

Check my progress: MCP deploy and test locally

### 2d. Deploy to Cloud Run (up to 10 minutes)

```bash
cd ~/mcp-on-cloudrun
gcloud run deploy `cat ~/mcpname` \
    --no-allow-unauthenticated \
    --region=`cat ~/region` \
    --source=. \
    --min=1 \
    --set-env-vars=FASTMCP_STATELESS_HTTP=true \
    --project=`cat ~/project` \
    --labels=lab-dev=mcp-zoo-cloud-run-service
gcloud run services describe `cat ~/mcpname` --region=`cat ~/region` --format='value(status.url)' > ~/mcpurl
cat ~/mcpurl
```

You should see the deploy finish and a service URL printed. On a CPU quota error, wait a moment and rerun. The real URL is now saved in ~/mcpurl; if it differs from what .env has, fix .env:

```bash
cd ~/zoo_guide_agent
sed -i "s|^MCP_SERVER_URL=.*|MCP_SERVER_URL=\"`cat ~/mcpurl`/mcp/\"|" .env
grep MCP_SERVER_URL .env
```

Check my progress: MCP deploy to Cloud Run

## Task 3. Update the agent to use MCP

### 3a. Tokens and MCP config (zero stray dollar signs, values read from files)

```bash
cat ~/mcpurl > ~/audience
gcloud auth print-identity-token --audiences="`cat ~/audience`" > ~/idtoken
mkdir -p ~/.gemini/config
cat > ~/.gemini/config/mcp_config.json <<'EOF'
{
  "mcpServers": {
    "zoo-remote": {
      "serverUrl": "AUDIENCE_X/mcp/",
      "headers": {
        "Authorization": "Bearer TOKEN_X"
      }
    }
  }
}
EOF
sed -i "s|AUDIENCE_X|`cat ~/audience`|; s|TOKEN_X|`cat ~/idtoken`|" ~/.gemini/config/mcp_config.json
grep -o '"serverUrl": "[^"]*"' ~/.gemini/config/mcp_config.json
```

You should see the serverUrl line with your real URL ending in /mcp/. The token is in the file, not shown. If Antigravity CLI later says the token expired, rerun this whole block.

### 3b. Use Antigravity CLI against the remote server

```bash
agy
```

In the CLI (sign in again if asked, same as Task 2):
- Type `/mcp` and confirm zoo-remote shows a green check with its tools. Press ESC.
- Ask: `Where can I find penguins?` and choose to always allow all tools from zoo-remote. You should get the answer with a box showing the MCP server was used.
- Run the custom command: `/find --animal="lion"`. It should call fetch_animals_by_species and format the result.
- Exit with `/quit`.

### 3c. Verify the server logs

```bash
gcloud run services logs read `cat ~/mcpname` --region=`cat ~/region` --limit=5
```

You should see a log line confirming a tool call was made.
